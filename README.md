# MIDS calculation based on GBIF snapshots from Darwin Core Archives

This repository includes code to calculate MIDS levels and information element achievements for snapshot data of GBIF. More info on the MIDS standard can be found on the [TDWG MIDS standard draft website](https://mids.tdwg.org/). This work is based on previous efforts to calculate MIDS at the full GBIF scale ([Dillen et al. 2025](https://doi.org/10.3897/biss.9.181898)), which used a snapshot of GBIF with Preserved Specimen records only, retrieved through the SQL API, and applied the [MIDSCalculator code](https://github.com/AgentschapPlantentuinMeise/MIDSCalculator) in batch on this large dataset (~120 GB).

The code in this repository operates on parquet snapshots instead, which offers significantly more efficient computational and I/O efficiency. GBIF has been offering monthly full parquet snapshots for several years now, but these only include selected properties, and some key ones for MIDS are missing (e.g. dwc:preparations). Because of these absent properties, we can only resort to full Darwin Core Archive snapshots as our historical data source. Such snapshots are available going back to at least 2016, though they have become increasingly unwieldy. Snapshots with only preserved specimen data also exist, but few data files have been retained by GBIF the further back in time we go, as many GBIF download payloads fail to get cited. 

## Data Acquisition

Hence, the workflow has been using parquet files derived from full GBIF DwC-A snapshots (including billions of observed birds). These massive files were downloaded to a machine with sufficient memory, where they were decompressed and the contents transformed into more wieldy parquet files. The workflow in this repository uses those parquet files. The [DuckDB](https://duckdb.org) scripts used to acquire and subset the Darwin Core Archive download payloads into Parquet files can be found in the `data` folder as Linux shell commands. `acquire_dwca.sh` was used to download the massive Darwin Core archives listed in `gbif_full_dwcas.tsv`, one by one. Then `duckdb_occurrence_file.sh` partitions the Archive's `occurrence.txt` file into distinct Parquet subsets based on their `dwc:basisOfRecord` value. For the analyses in this repository, we focused on records with `dwc:basisOfRecord` = `PRESERVED_SPECIMEN`, but the other partitions (in particular `FOSSIL_SPECIMEN`) can be processed similarly. `duckdb_multimedia_file.sh` and `duckdb_join_multimediaID.sh` respectively convert the multimedia.txt file to Parquet and join the presence of a Multimedia `dc:identifier` into the occurrence partition for Preserved Specimens. Finally, `duckdb_rejects.sh` inspects the number of cases where DuckDB failed to parse the data and why.

## MIDS Calculation

The main script is `parq.R`, which streams the parquet file using `arrow` and processes the file to calculate the MIDS level for each record, as well as retains the binary map for each information element. It also indexes some properties like country and year for downstream analysis. The calculation re-uses functions from the MIDSCalculator tool, which needs to be available on the same machine (its local path should be specified in `parq.R`). The result is written as a parquet file in the `outputs` directory. The location of the big Parquet file with all preserved specimen data from GBIF can be specified in `config.ini` under `parquetpath`. The other configuration parameters there can be ignored. A slightly adapted SSSOM mapping is included in this repository and used during the calculation to account for the way MediaID was flattened into the single Parquet file, and avoid ambiguity between the use of dc:identifier in Occurrence Core and Extension files.

## Calculation Analysis

The `analyze_results.R` script derives some summary statistics for each generated .parquet file and plots them into a barchart. `csv_summary.R` plots results for all years alongside each other. `compare_new.R` uses DuckDB in R to investigate patterns in new GBIF records, per year.

More elaborate analyses and visualizations based on the .parquet files are listed in the `analyses` folder. These analyses were performed with assistant of Microsoft Copilot. These analyses assume the parquet files are present in the `outputs` folder. These Parquet files are not included in this repository, but can be obtained from Zenodo: https://doi.org/10.5281/zenodo.23727612.
